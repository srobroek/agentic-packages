# Docs And Specs Index

Use this context when working on specifications, SpecKit assets, or documentation writing.

Apply the shared write-agentic current-state, technical-concision, and reader-value contract. Classify each document and keep only purpose-qualified content:

Ordinary documentation includes:

- current artifact
- reader actions
- prerequisites
- safety constraints
- invariants

Specifications, plans, and SpecKit assets include:

- testable future intent
- requirements
- constraints
- acceptance criteria

Architecture decisions and decision records include:

- the decision
- rationale
- rejected alternatives
- consequences

Migrations and change communications include:

- before/after comparisons
- migration actions

Historical records and reports include:

- dated facts
- findings

Procedures and references include:

- current operation
- reproducibility.

Read only the relevant detail.

- [Specification workflow context](docs-specs.spec-workflow.context.md). SpecKit is opt-in per project. Specifications apply regardless of mode.

Documentation-writing style rules for READMEs, documentation, and PR text live in the slopvac package.
