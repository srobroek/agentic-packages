# Hooks and MCP packages

## Hook packages

Opt-in lifecycle hooks. Most hooks ship inside their owning package (code-intelligence, agent-coder, the MCP packages, speckit); the two below are standalone cross-cutting policy packages.

A package ships universal `.apm/hooks/hooks.json` only when behavior is genuinely identical, otherwise it ships `.apm/hooks/<pkg>-{claude,codex}-hooks.json`, plus a `scripts/` directory. APM deploys target-specific config and rewrites `${PLUGIN_ROOT}`.

A script invoked by bare path (`${PLUGIN_ROOT}/scripts/guard.sh`, with no `uv run`, `python3`, or `bash` prefix) must be committed mode 755. APM writes the source mode on first deploy and thereafter skips content-identical files, so a mode-only fix never reaches an install that already has the wrong bit. `.apm/scripts/check-script-invocation.py` gates this on every PR, over both hook commands and runtime paths named in agent-facing markdown. Codex supports `SessionStart`, `SubagentStart`, `PreToolUse`, `PermissionRequest`, `PostToolUse`, `PreCompact`, `PostCompact`, `UserPromptSubmit`, `SubagentStop`, and `Stop`; all other events stay in Claude variants. Codex runs only synchronous command handlers, requires trust review for plugin hooks, does not support `permissionDecision: "ask"`, and does not intercept every unified shell or non-MCP tool path. Hooks are written in Python unless the script only forwards to one command; see [Codex compatibility](codex-compatibility.md) and the [hook contract package](../packages/agent-hook-contract/.apm/instructions/agent-hook-contract.instructions.md) for the language rule, the per-call performance budget, and the cross-tool event and decision tables.

| Hook Package | Description |
| --- | --- |
| `hooks-attribution-guard` | Advises against AI authorship attribution in git commits so the human stays the sole author of record. Covers agent trailers from any vendor (Co-Authored-By / Signed-off-by / Assisted-by naming Claude, Codex, Copilot, Cursor, Devin, aider, Gemini, OpenHands, Windsurf and others, or pointing at an agent noreply address), "Generated with/by" phrases, agent signature URLs, robot-emoji signature lines, and hyphenated AI-assisted/AI-generated qualifiers. Emits a non-blocking advisory (allow + additionalContext, exit 0); a commit message is trivially fixable, so it never blocks. Scoped to authorship constructs, so ordinary work that merely names an agent or a model ("fix AI model loading bug", "bump anthropic sdk") is not flagged. Cross-tool (Claude + Codex). |
| `hooks-bash-safety` | Bash safety guard tuned for autonomous agents, in one Python module with a real shell tokenizer. Denies only the unrecoverable: rm -rf on the filesystem root, a home root, or a system-critical tree (BS-4/BS-8), rm -rf whose target hides behind an unexpanded variable so the guard cannot verify it (BS-9), mkfs (BS-5), dd onto a real block device while allowing the pseudo-devices (BS-6), and the sandbox-bypass flag (BS-3). Warns without blocking on a curl-to-shell pipe, sudo with a destructive verb, and rm -rf outside the git working tree (BS-7, BS-10). Anything inside the working tree is assumed git-recoverable and passes silently, so wiping node_modules or a build directory says nothing. Because the command is tokenized rather than pattern-matched, wrapper prefixes, env assignments, leading tabs, quoted targets, flags after the target, path traversal, subshells, loop bodies, and a rebasing cd are all covered by construction. Never emits "ask". Cross-tool (Claude + Codex). |
| `hooks-chezmoi-guard` | PreToolUse advisory (non-blocking) for writes to files chezmoi ACTUALLY manages (exact membership in `chezmoi managed`, 60s cache). A managed target is a real file rather than a symlink to its source, so a direct edit succeeds and is then reverted by the next `chezmoi apply` with no error and no diff; this names that before the edit lands. Emits permissionDecision:"allow" + additionalContext pointing at the source -- the operation proceeds. Bound to the write tools (apply_patch/Edit/Write/MultiEdit), so a redirect-based shell write is not covered. Unmanaged paths and paths merely mentioned in a patch body are silent. Requires python3 on PATH. Cross-tool (Claude + Codex). |
| `hooks-close-keywords` | Fixes the GitHub "comma-list close" quirk, where a closing keyword binds to only the FIRST issue in a list (Closes #1, #2, #3 closes just #1). A shared normalizer distributes the keyword across every issue in a contiguous list (-> Closes #1, closes #2, closes #3) for close/closes/closed, fix/fixes/fixed, resolve/resolves/resolved. Two delivery layers: a pre-commit commit-msg hook that rewrites the message in place (tool-agnostic), and a PreToolUse guard on `gh pr create`/`gh pr edit` that emits a non-blocking advisory (allow + additionalContext carrying the corrected body) when a malformed comma-list close is detected. Requires python3 on PATH. Cross-tool (Claude + Codex). |
| `hooks-git-safety` | Git safety guard for autonomous agents, in one Python module with a real shell tokenizer. Denies exactly one thing: a destructive op aimed at another working tree through an unexpanded variable or ~, where the guard cannot resolve which tree is affected (GS-2). Everything else is non-blocking. reset --hard, checkout --, restore, and clean -f warn only when repository state shows work would really be lost (GS-3, GS-5, GS-6), so a clean tree stays silent and an untracked-only tree does not trip the reset rules. push --force always warns, because the loss is on the remote where local state cannot answer for it (GS-4). branch -D, tag -d, stash drop, and worktree remove --force pass silently, all being reflog-recoverable. State reads happen once, and only after a destructive verb matches. An unreadable tree warns rather than staying quiet. Never emits "ask". Cross-tool (Claude + Codex). |
| `hooks-package-investigate` | Non-blocking PreToolUse Bash hook that nudges the agent to investigate a dependency's trustworthiness, maintenance, quality, popularity, and alternatives BEFORE adding/installing it (lighter review for update/upgrade/remove). Requires python3 on PATH. Cross-tool (Claude + Codex). |
| `hooks-quality` | Non-blocking quality advisory on edits. Accumulates edited files and changed lines across a session and suggests targeted checks (ruff, gofmt, cargo fmt, biome) once the change is large enough to warrant one, then holds a cooldown so it does not nag. Commit-time formatting is deliberately not covered: that is the pre-commit framework's stage, and this hook advises per language only where the framework does not already run a checker for it, which needs both an installed framework hook and a config naming that checker. Language selection reads .agents/hooks/quality-languages, then AGENTIC_QUALITY_LANGS, then marker files, so an unrecognised project is silent rather than guessed at. Never denies. Thresholds via AGENTIC_QUALITY_ADVISORY_LINES, _FILES, _COOLDOWN_SECONDS. Cross-tool (Claude + Codex). |
| `hooks-serena` | Serena lifecycle hooks for Claude Code and Codex. Activates Serena at session start, reminds agents to use symbolic tools, and clears hook state at session end without configuring MCP transport. |
| `hooks-subagent-fork` | PreToolUse:Agent deny gate rejecting Codex spawn_agent calls whose fork_turns is "all", omitted (Codex defaults omitted to a full-history fork), or above the numeric maximum (default 3, SUBAGENT_FORK_GUARD_MAX overrides). Denials carry the corrected call format. A SubagentStart hook injects the fork_turns="none" discipline into spawning subagents, and an always-on instruction carries the same rule in the main session. Codex-only: Claude has no fork_turns concept, so the package does not target Claude at all. The hook fails open on malformed input. Requires python3 on PATH. |
| `hooks-subagent-model` | Claude PreToolUse:Agent deny gate requiring an explicit model when a spawn would inherit the parent session model. It allows explicit models and pinned agent types. Denials include routing guidance. SUBAGENT_MODEL_GUARD_INHERIT_TYPES adds unpinned types. The hook fails open on malformed input. Reasoning effort stays in reusable agent definitions because Agent calls have no effort field. Codex does not receive this hook. |
| `hooks-subagent-worktree` | Non-blocking worktree-isolation advisory on every subagent spawn. A PreToolUse:Agent hook injects a short reminder -- if the subagent WRITES files and runs in parallel with other writers, pass `isolation:"worktree"` (Claude branches it from your current HEAD); a read-only, different-repo, or lone-writer subagent needs none -- and if it does run isolated, to COMMIT before finishing so the worktree branch retains the work. It NEVER denies a spawn (superseding the 1.x deny-gate, which guessed wrong and blocked legitimate work) and stays silent once isolation is already declared. Claude-only (the Agent spawn tool is Claude-specific); the Codex variant is a no-op. Requires python3 on PATH. |
| `hooks-worktree` | Worktree lifecycle hooks: create worktrees outside the repo tree (in /tmp) to prevent nesting, and clean up the worktree directory and branch on removal. Claude-only WorktreeCreate/WorktreeRemove events; Codex requires explicit worktree wrapper commands because it has no equivalent lifecycle events. Both events route through one script, worktree-hooks.py. Requires python3 on PATH. |
| `hooks-worktrunk` | Enforces Worktrunk as the worktree-management interface for Claude and Codex. A cross-runtime PreToolUse guard denies direct git worktree and gh pr checkout commands with the equivalent wt command, a PreToolUse:Agent guard denies harness isolation:"worktree" in favor of a parent-prepared checkout, and Claude-only WorktreeCreate/WorktreeRemove handlers route the native worktree lifecycle through wt. Steering and config templates cover official plugins, agent checkout isolation, lifecycle hook ownership, repository-scoped build targets, copy-ignored warm starts, deterministic dev-server ports, aliases, and LLM commit generation. |

## MCP server packages

MCP-related runtime and integration packages. Pure server packages add a direct
runtime registration; integration packages retain hooks and steering while
expecting the MCP runtime to be configured separately by the environment.

<!-- BEGIN:mcp -->
| MCP Package | Description |
| --- | --- |
| `mcp-1mcp` | MCP client package for the shared 1MCP runtime. Starts the machine-managed background runtime when needed and connects clients through its proxy. |
| `mcp-codebase-memory` | MCP server package for the Codebase Memory MCP, providing graph-aware project orientation (symbol search, call paths, code snippets). Available but not wired by default; requires explicit installation and index build. |
| `mcp-context7` | MCP server package for Context7, providing current library and framework documentation lookups. |
| `mcp-fetcher` | MCP server package for Fetcher, providing direct web-page retrieval for coding agents. |
| `mcp-mempalace` | MemPalace lifecycle and steering package for a local-first cross-session memory layer. Files verbatim conversation/decision history into a vector + temporal-graph store (ChromaDB, local embeddings, zero LLM calls) and recalls it via semantic + temporal search. Ships a SessionStart hook that injects a tiny per-repo memory index (recall happens on demand via mempalace_search with a real query), a SessionEnd hook that automatically mines each completed session's transcript into the repo's wing (with FTS5 self-heal), a one-time backfill script for historical transcripts, and steering that scopes MemPalace to cross-session memory rather than current code structure. Complements semantic code intelligence; it is not code navigation. The MCP runtime is supplied separately by the environment. |
| `mcp-package-version` | MCP server for package version discovery |
| `mcp-playwright` | MCP server package for Playwright, providing browser automation and in-browser UI verification. |
| `mcp-repomix` | MCP server package for Repomix, providing bulk repository snapshots for analysis and review. The PostToolUse snapshot-refresh hook requires python3 on PATH. |
| `mcp-serena` | MCP server package for Serena semantic code tools. The launcher shares one Serena backend across agents in the same checkout, isolates linked worktrees, and applies resource and capacity limits to worktree backends. |
| `mcp-tauri` | Tauri MCP workflow guidance for building, testing, debugging, and driving Tauri v2 apps through an MCP runtime supplied separately by the environment. |
