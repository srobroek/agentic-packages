# project-setup — Tier-2 agentic features & gates roadmap

_Generated by the agentic-features-review workflow (4 of 5 survey areas; the
`gates-and-review` area crashed with an API error, so dedicated gate analysis is
PARTIAL — gates are covered inline per-opportunity but not as a standalone pass)._

Input for the **module-enablement-layer followup spec** (Task #7). NOT part of the
0–5 migration. The architecture's agent/gate seams are already built + tested;
these are net-new capability features.

## Executive summary

The architecture is sound and the agent/gate seams are already real: io_adapter.agent_step returns {answers_to_persist: {key: {value, source:"agent-steered"}}}, executor.run_agent_step/run_gate_step fold it back, and reproduce.py replays frozen agent answers without re-researching. So every Tier-2 opportunity reduces to the SAME shape: an agent picks among options + researches current versions, persists a frozen decision, a gate shows it, and a deterministic python step consumes the frozen answer via FrozenInputs and writes pinned manifests with idempotent_write. The survey produced ~24 ideas across 5 areas; after dedup they collapse to ~10 distinct features plus 2 cross-cutting runner affordances and a clear module-vs-skill split. The single highest-leverage cluster — and the one the user explicitly named — is FRAMEWORK + COMPANION-LIBS + VERSION resolution for python and ts: it appears in 4 of the 5 areas under different names and should be built ONCE as a generic resolver pattern (agent emits {framework, pinned_deps:[name@exact], rationale}; python writes the manifest) reused by lang-python, lang-ts, and package-add. A genuinely important finding: lang-python's existing step 4 (uv add --dev ruff pytest, module.py line 173) is UNPINNED — it resolves "latest" at run time, so the current Tier-1 module already silently violates byte-identical reproduction. The version-resolver work is therefore not just additive judgment; it closes a live determinism hole. The hard risk to the determinism guarantee is that all of these touch external generators and registries whose outputs are not byte-stable; the discipline that keeps Tier-1 honest is: agent freezes EXACT pins (never ranges, never "latest"), python never resolves, every pin is registry-verified before persist, and external scaffolders (create-next-app, uv init) are recorded-command + recorded-generator-version, gated, and skipped in CI.

## When a step earns Tier-2 (principles)

- A step earns Tier-2 (agent) status ONLY if its correct output is a JUDGMENT over OPEN-ENDED or TIME-VARYING data that cannot be enumerated in a manifest choice list: 'which framework fits this prose intent', 'which exact versions co-install today', 'is this existing dep a real conflict'. If the answer set is finite and stable, it is a manifest [[inputs]] choice/multichoice, not an agent.
- The agent decides; python writes. The deterministic boundary is invariant across every opportunity: the agent emits a FROZEN structured decision (ids, exact pins, a template_id, a prose block) into answers_to_persist with source=agent-steered; a python step reads it via FrozenInputs and mechanically renders the manifest/file with idempotent_write. The agent NEVER writes files and NEVER emits ranges or 'latest'.
- Research happens exactly once, then freezes. Tier-2 is allowed to call context7 / package-version MCP / whats-new at INIT only. Reproduce mode replays the frozen answer verbatim (no network), which is why byte-identity survives. Re-derivation must be an explicit, gated --refresh, never an implicit re-run.
- Every persisted pin must be registry-verified in the same run. A version the agent recalls but package-version MCP / PyPI JSON cannot confirm is rejected (treat as INPUT_VALUE_INVALID), because hallucinated/typosquatted/yanked pins are the dominant abuse mode. Canonical package names come from the framework's own current docs (context7), not free recall.
- The agent must leave slots EMPTY when the framework already owns them. Companion-lib selection defaults every capability slot (router/state/data-fetching) to 'none' and only fills it if the chosen meta-framework demonstrably does not provide it (confirmed via context7). A checkbox list invites redundant/conflicting libs; the agent's value is suppression.
- Agents pick among CURATED templates by id; they never emit raw config text. For test-runner config, CI YAML, ORM scaffolds, the agent chooses a template_id + fills a tiny known slot set; python instantiates the in-repo template. Freehand config is non-deterministic and frequently wrong against the real tool API.
- The blast radius determines the gate, not the kind. Any step that writes a dependency manifest, runs an external/network generator, mutates a shared file (root workspace manifest, AGENTS.md, CI that runs on push), or selects a supply-chain index-url MUST be human-gated and default-skip in --non-interactive/CI. Dev-only tooling pins and placeholder-only writes (.env.example) can pass a lighter or optional gate.
- Cross-module coherence constraints are validated deterministically in python, decided in the agent. The agent reconciles 'framework needs python>=3.12 vs frozen python_version 3.11' or 'async framework -> async driver'; the python step then RE-VALIDATES the frozen decision against the other frozen answers (requires_python, DB choice) and hard-errors on contradiction rather than trusting the agent blindly.
- If the correct output SHOULD change next month, it is a standalone SKILL, not a pipeline module. Upgrade-advisory and framework-migration have no reproduction contract; forcing them into a module pollutes the byte-identical model. They live as skills that READ answers.toml (frozen framework+pins) but never write it.

## Build first (recommended order)

1. Build stack-resolver (rank 1) FIRST as a single generic resolver pattern, then instantiate it for lang-python and lang-ts. It is the exact feature the user named ('which framework + which current versions + which companion libs'), it is the dominant duplicate across 4 of 5 survey areas, and building it once gives a reusable {agent emits pinned decision -> gate -> python writes manifest} template that ranks 2, 5, 7, 11 all reuse. It is also the first real exercise of the built-but-unused agent kind end-to-end, so it de-risks the whole Tier-2 program.
1. Build py-toolchain-pin-resolve (rank 2) SECOND because it is the cheapest way to prove the resolver pattern AND it closes a live determinism bug: lang-python/module.py line 173 runs `uv add --dev ruff pytest` unpinned, so today's 'Tier-1 byte-identical' module already drifts on re-run. Fixing it is both correctness and a small, self-contained first instantiation of the rank-1 pattern (dev-only tooling, lighter gate, lower blast radius than a full web stack).
1. Build the refresh/re-research gate (rank 3) THIRD because it is small and it is the structural guarantee that makes everything above SAFE. Without it, any future maintainer's plain reproduce risks silently re-researching and breaking byte-identity; with it, reproduce is provably network-free replay and re-derivation is explicit, per-key, and gated. Shipping it alongside the first two resolvers means the determinism contract is enforced by construction, not by convention.

## Ranked roadmap

### #1 stack-resolver (generic framework + companion-libs + version pinning, instantiated for python and ts)  _[high value / large effort]_
- **Area:** framework-selection (py+ts) / agentic-scaffolding / ecosystem
- One reusable Tier-2 resolver: agent maps prose intent -> {framework, exact-pinned companion set, rationale}; python writes pyproject/package.json from the frozen pins. Replaces the unused free-form `framework` string in lang-python/lang-ts.
- **Determinism boundary:** Agent decides framework id + the full {name@exact-version} map (deps + companions, sorted canonically) + rationale; emits as agent-steered answers. Python step is fully mechanical: merges the frozen pin map into the manifest via idempotent_write and runs the package manager with EXACT pins (no ranges, no 'latest'); re-validates each pin's requires_python/engines against the frozen language version and hard-errors on conflict. Reproduce replays frozen pins byte-identically; the generator/skeleton template is selected by frozen id.
- **Gate:** Mandatory file-write gate showing the full pin table with any downgrade-from-latest + reason before any manifest write; this is the highest-blast-radius decision (supply-chain surface). Default-skip scaffold/install in --non-interactive/CI.

### #2 py-toolchain-pin-resolve (pin ruff/pytest/type-checker; close the existing determinism hole)  _[high value / medium effort]_
- **Area:** framework-selection-py
- Upgrade lang-python step 4 (`uv add --dev ruff pytest`, currently unpinned 'latest' at module.py:173) into an agent-resolved pinned dev-tool block, and derive the ruff-pre-commit hook rev from the SAME frozen ruff version.
- **Determinism boundary:** Agent decides the dev-tool name set (incl. type-checker choice mypy/pyright/ty), the intent-gated plugin set (pytest-asyncio only if async framework frozen), and each exact pin. Python writes [dependency-groups].dev in canonical sorted order AND sets the astral-sh/ruff-pre-commit rev to the resolved ruff version so local run and CI hook agree. Today the unpinned 'uv add' makes re-runs install different versions — this step makes Tier-1 actually byte-identical, so it is bug-fix + judgment in one.
- **Gate:** Light module-level confirm showing the dev-tool pin table + the derived hook rev; may auto-approve in CI since dev-only, but must record provenance + research source.

### #3 refresh/re-research gate (runner-level --refresh + diff-confirm)  _[medium value / small effort]_
- **Area:** ecosystem-and-maintenance
- The seam that makes time-varying research SAFE: a --refresh <module|key> flag that is the ONLY mode allowed to re-invoke agent research and re-persist, behind a per-key old-vs-new diff confirm. Plain reproduce never researches.
- **Determinism boundary:** Default reproduce = byte-identical replay of frozen agent-steered answers, zero network. --refresh re-runs the agent for the named keys and shows old vs newly-researched value; a python step then writes deterministically from the newly frozen answers. Determinism is never violated silently — re-research is always explicit and gated.
- **Gate:** Mandatory diff-confirm gate, per refreshed key; nothing re-persists or re-writes without confirm. Reuses the existing reproduce diff/confirm machinery.

### #4 agents-md-architecture-section (stack-aware conventions in AGENTS.md)  _[high value / medium effort]_
- **Area:** agentic-scaffolding-content
- Agent reads the frozen answer set (layout, languages, resolved framework/pins, speckit) + a read-only tree scan and writes a project-specific Architecture & conventions section; python splices it into AGENTS.md between BEGIN/END sentinels.
- **Determinism boundary:** Agent decides one `architecture_md` text block + a list of agent-editable globs (agent-steered). Python wraps it in fixed `<!-- BEGIN ps:architecture -->`/END sentinels, splices ONLY that span via idempotent_write(reconcile=true), and validates referenced top-level dirs actually exist (warn, never write phantom paths). Frozen answer -> identical bytes; persisted as project provenance so re-runs replay it.
- **Gate:** kind=gate showing the rendered section diff before the splice — AGENTS.md steers every future agent in the repo, so the write is confirmed.

### #5 ci-matrix-sized-to-stack (new ci-github-actions module)  _[high value / medium effort]_
- **Area:** agentic-scaffolding-content
- Agent synthesizes a CI job graph sized to the actual stack (per-language jobs, current supported runtime matrix, current setup-action majors); python renders canonical .github/workflows/ci.yml and validates every command against real justfile recipes/manifest scripts.
- **Determinism boundary:** Agent decides the `ci_plan` (jobs, matrix entries, action refs pinned to current majors, commands). Python validates each command exists in the scaffolded justfile/manifests (drops/warns on unknowns), then emits canonical YAML via idempotent_write. Same frozen ci_plan -> identical YAML; action majors persisted so drift is intentional.
- **Gate:** kind=gate showing the rendered workflow before write; CI that runs on push is consequential and easy to get subtly wrong (deprecated node-runtime actions, over-broad matrix burning minutes).

### #6 brownfield-detect-and-adopt (stack inference -> enable+answer modules)  _[high value / large effort]_
- **Area:** ecosystem-and-maintenance
- Default-enabled Tier-2 module running FIRST on non-empty repos: agent inspects lockfiles/manifests/config and proposes which lang overlays to enable, what answers each gets, and which base modules to SKIP as already-satisfied.
- **Determinism boundary:** Agent decides {module_id -> enabled?} + per-module answer values (package_manager, framework, python_version) as agent-steered answers; writes ZERO files. Once frozen in answers.toml the whole run is reproducible on a clone exactly like a greenfield run. The agent only sets answers for existing trusted modules — no arbitrary code path, and detected env-file secrets are never read into answers (no-secret-type invariant holds).
- **Gate:** Module-level gate AFTER the agent step: show the enable/skip set + inferred answers + root/leaf classification as a diff-like summary; require >=2 corroborating signals before proposing enablement. Brownfield equivalent of validate-closed review.

### #7 py-web-stack-select + py-data-orm-select (deep python web/persistence overlays)  _[high value / large effort]_
- **Area:** framework-selection-py
- Specialization of the rank-1 resolver for the python web tier (FastAPI/Litestar/Django + ASGI server + pydantic-settings) and the data tier (SQLModel/SQLAlchemy async-vs-sync + DB driver matching the DB-in-prose + alembic only if ORM chosen).
- **Determinism boundary:** Agent decides framework/orm id, async-vs-sync flavor, driver name, migration-tool presence, and each exact pin (cross-checked so an async framework gets asyncpg not psycopg2, and SQLModel<->SQLAlchemy versions resolve from one research pass). Python pins + uv add with frozen versions + scaffolds alembic/models from static templates keyed on frozen ids; re-validates driver-vs-DB and requires_python-vs-frozen-python and errors on mismatch.
- **Gate:** File-write gate on the pin table + the new structural files (alembic.ini, migrations/env.py, models stub) — hard to unwind, so confirm before scaffolding.

### #8 dependency-update / upgrade-advisory as a STANDALONE skill  _[high value / medium effort]_
- **Area:** ecosystem-and-maintenance
- A skill (sibling to whats-new/dep-audit) that reads an already-scaffolded repo's lockfiles, researches whether bumps are safe, and produces a cited upgrade plan; applies only patch/minor behind confirm. NOT a pipeline module.
- **Determinism boundary:** Explicitly OUTSIDE the determinism contract: its correct output is time-varying and should differ next month, so it must NOT be a module (which freezes for reproduction) and must NOT write answers.toml. The only project-setup touchpoint is that the scaffold LEAVES durable inputs (pinned versions + recorded framework in answers.toml) for this skill to read.
- **Gate:** Per-bump confirm; never auto-applies majors (advisory-only). Inherits dep-audit's read-only-by-default posture.

### #9 env-example-from-stack (.env.example derived from stack)  _[medium value / small effort]_
- **Area:** agentic-scaffolding-content
- Agent derives canonical env var NAMES from the framework + companion libs (NEXT_PUBLIC_/VITE_ prefixes, DATABASE_URL, framework SECRET_KEY names); python writes .env.example with placeholders ONLY.
- **Determinism boundary:** Agent decides the `env_keys` list (name, placeholder text, comment, secret_bool used ONLY to pick comment wording). Python emits one KEY=placeholder line per entry, sorted, via idempotent_write, and HARD-REFUSES any value that isn't a literal placeholder token — upholding the no-secret-type invariant. Fixed output filename (agent has no say over the path, so it can never write a real .env). Same frozen list -> identical bytes.
- **Gate:** Optional kind=gate (low blast radius, placeholders only); recommended so the dev sees the inferred config surface but gate=none is acceptable if effort-constrained.

### #10 stack-decision-record + reproduce-time staleness check (ADR/STACK.md + advisory)  _[medium value / small effort]_
- **Area:** framework-selection-ts / agentic-scaffolding-content
- Deterministic STACK.md/ADR written from all frozen decisions (no agent needed), PLUS a reproduce-only agent step that flags whether frozen pins are now materially stale/CVE'd — advisory only, never mutates pins.
- **Determinism boundary:** The decision-record write is pure python (byte-identical from the answer set; ADR number = deterministic max+1 scan, date = frozen plan timestamp not wall-clock). The staleness check agent NEVER mutates pins/package.json — it emits an advisory note + severity surfaced at a gate; acting on it is a separate explicit human decision. Tier-1 reproduction stays byte-identical.
- **Gate:** Informational reproduce-mode gate showing staleness/CVE findings (default proceed, must NOT block reproduction); no gate for the deterministic record write. Severity threshold in steering to avoid fatigue (flag only high/critical or hard deprecations).

### #11 ts-test-tooling-resolver + ts-ui-kit-resolver + ts-runtime-pm-resolver (ts depth)  _[medium value / medium effort]_
- **Area:** framework-selection-ts
- Three coherent specializations of the rank-1 resolver for TS: test runner matched to build tool (Vitest/bun:test/Playwright via curated config template_id), UI kit matched to ui_lib+styling (shadcn/Tailwind v4) behind a gated init command, and Bun-vs-Node runtime + corepack packageManager pin.
- **Determinism boundary:** Agent decides runner + template_id + pins / ui_kit + literal init command + pins / runtime + node_line + exact packageManager pin. Python instantiates the chosen IN-REPO config template (never freehand config), writes engines/packageManager/version-file from frozen values, and runs UI-kit init ONLY behind a gate else writes a STACK-NOTES note. Python validates packageManager matches name@semver shape. Runtime resolver must run [order] BEFORE the scaffold so the generator uses the agreed PM.
- **Gate:** Test/runtime resolvers fold into the dependency-approval gate (light). UI-kit init REQUIRED gate before any network/file-generating init command; default-skip in CI; reproduce marks kit-init review/skip (non-idempotent clobber risk).

### #12 org-convention overlay + monorepo package-add resolver + readme-draft (extension-point patterns)  _[low value / medium effort]_
- **Area:** ecosystem-and-maintenance / agentic-scaffolding-content
- Lower-priority extension demonstrations: a private-git-source org-policy reconciliation module, a Tier-2 upgrade to package-add that aligns a new monorepo package's framework/versions with sibling pins, and a README drafted from frozen scaffold facts.
- **Determinism boundary:** All follow the standard seam: agent decides overrides/alignment/sections (agent-steered); python writes deterministically. package-add MUST keep its existing path-traversal guards (is_safe_relative_path) verbatim and run them before any mkdir — agent decisions cannot relax them. README uses reconcile=false (write-once, never clobber a hand-edited README). Org sources execute arbitrary code, so must be pinned by ref/tag in sources.toml.
- **Gate:** Org overlay: gate showing every policy-forced override (user-asked vs mandated). package-add: file-write gate on new manifest + confirm on the shared root-workspace-manifest edit. README: gate on first draft only (reconcile=false guards re-runs).

## Risks

- Pin freshness vs byte-identity is the core tension: a frozen pin is reproducible but rots; the honest answer is that Tier-1 reproduction is byte-identical ONLY for the same frozen answers + same generator version, NOT across time. External generators (create-next-app, uv init, shadcn init) are NOT byte-stable even at a pinned CLI version, so any module that runs them can only promise 'same recorded command + recorded generator version', which must be surfaced at the gate and skipped in CI — do not over-claim byte-identity for scaffold steps.
- Hallucinated / typosquatted / yanked pins are the dominant abuse mode. Mitigation must be structural: every persisted version is registry-verified (package-version MCP / PyPI JSON / uv add 404 = hard error) in the same run, canonical names come from context7 docs not free recall, and the gate surfaces full package names for human eyeballing. A resolver that trusts the agent's recall is a supply-chain hole.
- Supply-chain index-url surface (the py-ml torch CUDA case) lets an agent write an arbitrary extra-index-url into pyproject — restrict to an allowlist of official documented indices surfaced from research, and hard-gate; never auto-run in CI.
- Determinism leak via implicit re-research: if any agent step re-runs on a plain reproduce it will drift. This is only safe if reproduce.py strictly replays frozen agent answers and re-derivation is gated behind --refresh. Verify reproduce-mode replay has zero network calls for agent steps before shipping any resolver.
- Gate fatigue and CI deadlock: too many mandatory gates make the tool unusable and block --non-interactive runs. Calibrate by blast radius (manifest/generator/shared-file = hard gate + CI default-skip; dev tooling / placeholder writes = light/optional gate), and ensure every hard gate has a defined non-interactive default (skip, not auto-run).
- Prompt-injection and over-eager adoption in brownfield/scan steps: a scanned repo file is read-only context never executed, agent output is treated as text not code, and adoption requires >=2 corroborating signals + a confirm gate — otherwise a stray fixture file silently mis-enables a language overlay or a malicious repo steers answers.
